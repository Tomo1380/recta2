## 👍 強い・良いと思った点

1. **AIファースト導線が今っぽくて強い** — どのページもAIチャットが起点。「条件に合うお店を探したい→お任せください」の体験は、自分でフィルタを組み立てられない初心者に刺さる。選択チップ（高時給順/体入できる/日払いOK…）も迷わせない。
2. **ブランドの一貫性** — ダーク＋ゴールドの高級感。ナイトワーク媒体として信頼感と非チープ感。
3. **意思決定材料が揃ってる** — 評価★・口コミ件数・体入確約/未経験歓迎/送りあり等のタグ・時給レンジ。「このお店どうなん？」に答える素材は十分。
4. **回遊の整備（今回のコラム刷新）** — 読み物→店舗→LINE の動線が通った。

## ⚠️ 気になったUX課題（優先度順）

### 🔴 1. 店舗詳細が長すぎる（最重要）
店舗詳細が超ロングスクロール（ヒーロー→店舗情報→AIチャット→LINE→報酬表→写真→地図→セット料金→…）。求職者がモバイルで「ここにLINEするか？」を判断するのに、**決め手（時給・体入条件・エリア・雰囲気）が縦に散らばってる**。
- 提案: ファーストビュー直下に**意思決定サマリカード**（時給/体入/エリア/評価を1枚に）＋詳細は「もっと見る」で段階開示。スクロール位置に追従する**ミニ判断バー**（時給＋LINEボタン）があると離脱前にCV取れる。

### 🟠 2. LINE CTAの飽和（押し売り感のリスク）
右下FAB「たった1分で体入確約」＋インラインカード＋下タブ＋バナー…と**LINE誘導が常時多重**。コンバージョン意図は◎だが、初回訪問の慎重な子には圧が強い／逆に無視される（バナー盲）恐れ。
- 提案: FABは**スクロール／滞在で“温まってから”出す**、コピーは画面ごとに少し変える、同一画面のCTA数を絞る。A/Bで「常時 vs 温まり後」を比較する価値大。

### 🟠 3. トップの選択肢過多（Paradox of Choice）
トップが「AIに聞く・検索・エリア・業種・ピックアップ・履歴・新着・コラム」と一度に全部提示。初訪問者がどこから手をつけるか迷いやすい。
- 提案: **第一の道を1本**に強く（例：「まずAIに1分」を主役、探すは従）。離脱率と相談数で効果が見えるはず。

### 🟡 4. AIチャットの重複表示
トップ・一覧・詳細すべてに大きめのAIブロック。詳細では**その店舗特化**になってる（コード上◎）が、視覚的に本文を押し下げてる。詳細では折りたたみ or 「この店について聞く」ボタン化で本文への到達を早めても良いかも。

### 🟡 5. 桜口コミの信頼トレードオフ（今回実装した分）
桜/有名嬢口コミは業界標準だが、“盛ってる感”を察知されると一気に信頼が崩れるのがUX上の弱点。リアル口コミと演出口コミの見え方を作為的に寄せすぎない（有名嬢は「PR」明示等）方が、長期の信頼とCVに効く可能性。

## 🎯 ターゲット視点での観察
ナイトワークは不安と隣り合わせの意思決定。今のUXは「速い・簡単・体入確約・1分」とスピード／確約に振り切ってて、CVには強い。一方で初回の慎重層には「相談しやすさ・安心」の軸（顔出し相談・先輩の声・しつこくされない約束）をもう一段見せると、**上京×初心者**の取りこぼしが減ると思う。スピード訴求と安心訴求のバランスが、たぶん一番効くレバー。

  `recta_episodes` 等の自由入力を素材に、「雰囲気・働く人・安心ポイント」を

    migration `..._add_ai_intro_to_stores_table`（`ai_intro` / `ai_intro_hash`）。
    素材テキストの md5 が変わらなければ再生成しない（1店舗1回課金・以降即時）。
    `PublicStoreController::show` で lazy 生成、`StoreResource` が `ai_intro` を返す。
  - frontend: `AiChatPanel.getIntroScript` が `ai_intro` を優先表示（無ければ
    相談促進の最小 fallback）。

    再生成/素材なし/キーなし）。

  - test: `frontend/app/components/user/StoreDetailPage.dailyPay.test.ts`。

### ✅ LINE CTA を「温まってから出す」（課題 #2）
右下 FAB (`UserFab`) は `routes/user/layout.tsx` で全ユーザー画面共通の単一
コンポーネントとして常駐していたため、訪問直後から LINE 導線が出っぱなしで
押し売り感があった。→ **warm-up ゲート**を追加し、温まってから表示する。

- ロジック: `frontend/app/hooks/useFabWarmUp.ts`（`isScrolledEnough` 純粋関数 +
  hook）。判定 = **画面2枚分スクロール or 10秒滞在の早い方**。一度温まったら
  `sessionStorage` で**セッション中は出し続ける**（全画面同じルール）。
- `UserFab` の LINE ボタンを `warmed` でゲート、生の遷移時のみ登場アニメ
  （`fab-warm-in` / prefers-reduced-motion 配慮）。比較ボタンは対象外（店追加=別シグナル）。
- test: `frontend/app/hooks/useFabWarmUp.test.ts`。
- 実機確認: 初回 LINE FAB 非表示 → 2枚スクロールで登場＋flag 立つ →
  別画面遷移で即表示（セッション永続）。
- 補足: 下タブ(BottomTabBar)は撤去済み・本文中の `LineCtaCard` は文脈型なので
  warm-up 対象は常時オーバーレイの FAB のみ。
- 次の検証: 「常時表示 vs 温まり後」で LINE 追加率の A/B。
