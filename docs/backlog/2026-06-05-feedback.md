### ⚠️ LINE 追加の帰属に関する設計上の制約
LINE 公式アカウント友だち追加URLは全員共通で、追加完了 webhook(`follow`)は LINE
サーバー発のためブラウザ経路（cookie/IP/参照元）を持たない。**LIFF を使わない限り
「どの店舗/経路経由の友だち追加か」は確実に紐付け不可**（CLAUDE.md でも LIFF は Phase 4）。
そのため:
- **経路別ランキング = クリックベース（intent）** … 店舗/エリア/コラム/アフィリエイト別に正確
- **友だち追加 実績 = `line_friends`（全体トレンドのみ）** … 経路別には割れない

将来 LIFF を導入すれば実績の経路帰属も可能（F案件）。

#### 運用向けの調整（2026-06-05 追加）
- **「LINE導線クリック（押下）」と「友だち追加 実績（全体）」を明確に分離**して表示。
  「LINE追加数」という誤解を招く文言を排除（クリック=intent、実追加=全体のみ）。
- **グローバルCTA（右下FAB・下タブ）を“今いる画面”基準で帰属**。
  `tracking.ts` のアンビエント・コンテキスト方式: 各ページの `useTrackPageView` が
  現在画面（page_type/store_id 等）を保存し、文脈を持たないCTAが押されたら自動で拾う。
  → 「店舗詳細を見ながら右下FABでLINE追加」が店舗別に集計される。
- 帰結: 個別CTAに手動で文脈を渡さなくても、`useTrackPageView` を呼ぶページ上のCTAは
  自動でその画面/店舗/コラムに帰属する（コラム末尾CTA等も自動対応）。
- **画面×店舗クロス集計（ドリルダウン）**: ランキング行クリックで、その店舗/コラム/エリアの
  LINE導線を画面別に展開（例「○○店の 店舗詳細:下部カード から N クリック」）。
  `GET /api/admin/analytics/breakdown?type=&key=&days=` + `RankingService::lineSourceBreakdown`。
